# 泡泡看市待实施功能清单

> 更新日期：2026-08-22
> 口径：只列“尚未落地”或“仅有基础版、尚未达到产品可用标准”的事项；已经完成的个股基础快照、三表字段、技术指标、行业分位基础版、估值情景、事件重大性规则、六平台热榜、舆情基础页面不重复列入。

## 一、最高优先级：数据持久化与稳定性

### 1. PostgreSQL 生产持久化与备份

**状态：未完成（代码具备降级能力，当前本地预览仍使用内存仓储）**

- 在云服务器启动 PostgreSQL 容器，配置真实 `DATABASE_URL`，执行建表与迁移校验。
- 将早报、市场快照、个股报价、舆情原始内容、事件簇、用户账号与自选数据写入持久库。
- 配置每日自动备份、保留周期、恢复演练、磁盘告警和数据库健康检查。
- 服务重启后验证历史内容、关注列表和舆情观测不会丢失。

**为什么优先：** 没有持久库，缓存、舆情历史和“已落库”内容都会随服务重启消失。

### 2. 数据源运行监控与限流治理

**状态：部分完成（已记录部分来源健康度）**

- 统一记录各来源成功率、延迟、429/403、验证码、最后成功时间与回退层级。
- 为公开网页接口增加按来源限频、指数退避、熔断与最近成功快照回退。
- 增加运营页或健康接口，区分“数据源不可用”“当前无匹配内容”“数据库不可用”“AI 不可用”。
- 为妙想、GLM、知乎等有额度的服务增加调用量、失败率与成本监控。

## 二、事件与舆情 Agent 深化

### 3. 热榜候选的自动事实核验

**状态：基础候选池已完成，核验链待实施**

当前热榜只作为发现线索，不进入事件结论。下一步：

```text
热点候选 → 公司实体消歧 → 原文/权威搜索 → CNINFO、交易所、公司公告或权威媒体交叉核验 → 事件簇 → 事件 Agent
```

- 增加公司别名、产品名、高管名、品牌名与上下游关系的实体词典。
- 对同名公司、泛行业词和模糊产品词进入人工复核队列，不自动关联。
- 记录核验状态、核验依据、失败原因和证据 ID。

### 4. 社区原始内容与真实观点抽取

**状态：知乎搜索基础接入；微博/抖音/B 站/头条等仅接入热榜标题，不等于社区正文**

- 在取得合法、稳定授权后，接入帖子/回答/评论的正文摘要、发布时间、互动量、作者标识与原文链接。
- 将每条内容拆成：观点方向、论点、讨论对象、置信度、事实/观点属性。
- 以可追溯内容为基础计算正/负/中性占比、观点熵、集中度与变化趋势。
- 现有词典分类保留为兜底；后续用人工标注样本校准，不让模型自行编造立场。

### 5. 传播链、作者影响力与异常传播

**状态：基础事件簇、标题去重和事实链已完成；传播分析待深化**

- 识别同源转载、首发源、引用链、短时集中扩散和低质量重复内容。
- 在来源允许的前提下识别认证作者/高互动作者；不把粉丝数或单篇热度直接等同于可信度。
- 建立疑似营销、谣言、官方澄清与后续验证的生命周期提示。
- 新增人工确认/纠错入口，供运营或研究人员修正实体匹配、来源质量和事件归属。

### 6. 舆情历史、市场反应与阈值回测

**状态：基础热度与 3 日事件窗口已完成，长期序列和校准待实施**

- 将热度观测永久写入 PostgreSQL，支持 1/7/30 日历史分位。
- 补齐事件当日、1/3/5/10 日收益、成交量、换手率、波动率，以及相对大盘/行业表现。
- 对重叠事件输出“不可归因”，避免把同一时段行情归因给单条新闻。
- 基于历史样本回测关注度、事件反应、分歧等级阈值，替代长期固定经验阈值。

## 三、基本面与财报研究深化

### 7. 巨潮报告表格解析质量提升

**状态：年报/半年报基础解析、页码证据与 OCR 兜底已完成；复杂表格仍需增强**

- 强化合并单元格、总项/子项层级、跨页表格、多级表头和单位识别。
- 对“分产品、分地区、分行业”建立专门抽取规则：优先总项，避免总项与子项重复计数。
- OCR 结果增加置信度、表格结构校验与人工复核；低置信结果不能进入确定性结论。
- 扩展分业务收入、利润、占比、增长来源、集中度与业务恶化信号的长期序列。

### 8. 银行专属财务模板完善

**状态：普通非金融企业模板较完整；银行关键指标待补齐**

- 从定期报告结构化提取净息差、不良贷款率、拨备覆盖率、资本充足率、关注类贷款等。
- 形成银行专属的增长、盈利质量、资产质量、资本与流动性评分口径。
- 禁止复用普通企业的存货、经营现金流/利润、资产负债率等评价规则。

### 9. 分业务与一致预期数据源

**状态：分业务基础解析可用；一致预期未稳定接入**

- 评估并接入合规的券商一致预期、盈利预测修正与实际业绩偏离数据源。
- 将“公司业绩预告”与“市场一致预期”明确区分，不混用“超预期”的含义。
- 补充分业务利润、订单、产能、价格与经营指标的交叉验证。

## 四、行业与产业链 Agent 深化

### 10. 行业数据覆盖与指标质量

**状态：行业成员、基础财务分位、产业链映射和部分指标已完成；覆盖不均衡**

- 为不同行业建立可配置的上游价格、库存、产销、需求、开工率等指标模板。
- 补齐行业成员全量快照、停牌/新股/缺报/极端值处理和报告期对齐的生产调度。
- 以行业中位数、分位数、样本数和数据日期约束解释，避免把有限样本当成行业结论。
- 逐步建立“公司业务 → 上游材料 → 下游需求 → 景气指标”的可审计映射库。

### 11. 行业事件向公司影响的验证

**状态：行业/政策事件簇已接入；传导验证不足**

- 对政策、商品价格和行业新闻标记影响范围、受益/受损路径、有效期与核验指标。
- 只有公司公告、经营数据或后续财报支持时，才将行业事件升级为公司层结论。
- 处理行业事件重叠、政策落地节奏与跨行业公司归属问题。

## 五、估值与技术研究深化

### 12. 估值可比与情景校准

**状态：PE/PB/PS、历史位置、同行样本和 DCF/剩余收益基础情景已完成；数据完整度仍不稳定**

- 提升行业可比样本的完整性、报告期一致性与企业类型匹配。
- 为行业建立差异化假设，而不是长期使用统一折现率、永续增长率或简单利润增速。
- 在取得合规一致预期后，展示预期变化、实际业绩偏离与估值敏感性。
- 对亏损企业、银行、高资本开支企业分别完善适用模型与不可用提示。

### 13. 技术与市场信号回测

**状态：日 K、均线、MACD、RSI、波动率、回撤、关键位和相对强弱基础版已完成**

- 回测不同市场环境下的趋势、支撑/压力、结构失效与波动阈值。
- 完善复权、停牌、除权除息、上市时间不足与行业基准缺失的处理。
- 可选增强：分时数据、成交结构、资金流指标；必须先验证口径和稳定性。

## 六、尚未启动的产品能力

### 14. 组合风险 Agent

**状态：未启动**

- 输入用户持仓、成本、行业暴露、风险预算和现金比例。
- 计算集中度、相关性、最大回撤压力、行业暴露和单股风险贡献。
- 输出最大允许仓位、集中度提示与条件式风险说明；不自动交易。

### 15. 智能选股与研究候选池

**状态：未启动**

- 用可解释条件筛选形成候选池，再进入现有多 Agent 研究流程。
- 展示每项筛选条件、数据日期、排除原因与数据缺口。
- 定位为研究候选，不输出“自动推荐买入”。

### 16. 用户自带 AI Key / 无 AI 模式产品化

**状态：无 AI 确定性回退已具备；用户配置与版本切换未完成**

- 提供“仅程序研究”与“AI 解释增强”两个明确模式。
- 用户自填 Key 必须服务端加密存储、脱敏显示、可撤销，并限制可调用模型和额度。
- AI 失败时保持确定性结论可用，并明确降级范围。

### 17. 桌面 Web 端与跨设备体验

**状态：响应式基础已开始；完整桌面信息架构待实施**

- 根据设备宽度切换移动/桌面布局，后端数据与账户保持共用。
- 桌面端重点优化市场地图、研究对比、证据检索、财务趋势和多股票并排查看。
- 完成 320px、375px、768px 与常见桌面宽度的回归验收。

### 18. 授权型自选、模拟组合与内容运营

**状态：后置，暂不开发**

- 东方财富自选同步：先只读导入，再由用户确认写入；不默认双向同步。
- 模拟组合：用于组合风险验证，所有模拟交易动作需用户明确确认。
- 内容运营：与研究产品隔离，发布、点赞、评论必须人工复核与显式授权。

## 推荐下一步顺序

1. **部署 PostgreSQL、备份和健康监控**：先让已有数据真正可持续。
2. **热榜候选自动核验 + 实体词典**：让新增热榜能安全地转化为事件线索。
3. **社区正文/互动量接入与观点抽取**：让“舆情”从热点发现升级为可解释的市场预期观察。
4. **舆情历史和事件后多窗口回测**：校准规则、提高结论可信度。
5. **复杂财报表格与银行模板**：提升基本面覆盖质量。
6. **行业指标模板与行业传导验证**：让行业 Agent 不止停留在映射和分位。
7. **组合风险与智能选股**：在单股研究稳定后再扩展产品边界。

## 不应提前做的事

- 不把热榜、搜索摘要或单篇社区观点直接当作公司事实或买卖信号。
- 不在没有持久数据库前依赖“历史趋势”“已落库”或用户数据恢复能力。
- 不在缺少可复现样本和回测前，把经验阈值包装成长期有效规则。
- 不在未取得授权和作者元数据前，把任何账号直接标为“大 V”或“权威观点”。
