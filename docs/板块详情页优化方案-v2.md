# 板块详情页优化方案 V2

> 状态：待实施
>
> 基线：`main @ 0cd6f3e`
>
> 目标分支：`260807-optimize-sector-detail`

## 1. 目标与边界

将板块详情页从“行情字段清单”升级为“可验证的板块研判页”。用户打开页面后，应在首屏得到四个答案：

1. 今天发生了什么；
2. 是多数成分股共振，还是少数股票带动；
3. 有哪些可追溯的驱动证据与反向证据；
4. 接下来观察什么，而非获得买卖建议。

页面只展示已有行情、新闻、规则计算与早报 P1/P2/P3 的结果；无证据时明确说明证据不足，不补写原因。

不在本次范围内：个股买卖建议、仓位/目标价、逐股 K 线拉取、为每个板块新增一次 AI 调用。

## 2. 现状问题

当前 `SectorDetailPanel` 的首屏只有涨跌幅和多个折叠标题。核心解释均被收起，且默认打开的 `overview` 并不存在，因此用户进入详情后看不到板块结论。新闻、健康度、领涨股、观察项是平铺的独立模块，缺少“事实 → 证据 → 风险”的阅读顺序。

## 3. 信息架构与首屏

### 3.1 首屏：结论优先，默认展开

将以下内容固定为非折叠区，控制在一屏内：

| 区域 | 内容 | 来源 |
| --- | --- | --- |
| 板块概览 | 名称、涨跌幅、多周期表现、阶段、更新时间、关注按钮 | 现有行情接口 |
| 一句话结论 | `whatHappened`；没有高质量匹配时使用“当前观察到的市场变化” | P1 / 规则兜底 |
| 健康度摘要 | 普涨扩散 / 龙头带动 / 内部分化；上涨比例、样本覆盖率、Top3 贡献度 | `fetchSectorBreadth` |
| 证据状态 | 已确认催化 / 仅有行情事实 / 证据不足，以及证据数量 | P2/P3/新闻 |
| 观察提示 | 1–2 个最重要的后续观察指标 | P3 / 规则兜底 |

首屏不要使用“所有内容都是折叠卡”的结构。结论与风险必须默认可见；细节采用渐进展开。

### 3.2 二级内容：四组而非八组

1. **发生与结构**：板块内部表现、细分方向、健康度指标。
2. **证据与反证**：可信催化、相关新闻、反向证据；每条都标注来源与时间。
3. **代表股票**：今日强势、行业龙头、异动股票三组，只陈述当前表现和入选原因。
4. **后续观察**：观察指标、数据缺口与不确定性。

仅将二级细节设计为可展开区。首次进入时，“发生与结构”展开；其余区块收起。空数据不渲染空卡，只显示一条清楚的降级说明。

## 4. 数据与规则

### 4.1 板块健康度

复用 `fetchSectorBreadth`，并增加：

- `dispersion`：使用 P90 - P10 涨跌幅，不使用 max - min，避免单只异常股票扭曲结果；
- `turnoverRate`：东财 `f8`，供代表股排序使用；
- `sampleCoverage`：实际返回成分股比例；
- `dataAsOf`：行情数据时间。

健康度采用两个层级：机器状态与用户文案。机器状态继续兼容 P5 的 `broad_rise`、`leader_driven`、`divergence`；当板块整体下跌时，前端文案必须改为“多数回落”或“弱势分化”，不能误称“龙头带动”。

| 文案状态 | 建议判定 |
| --- | --- |
| 普涨扩散 | `upRatio ≥ 70%`，且 Top3 贡献度较低 |
| 龙头带动 | 板块上涨，且 Top3 贡献度高或上涨覆盖率低 |
| 内部分化 | 上涨覆盖率中间区间，或 P90-P10 离散度较大 |
| 多数回落 | 下跌覆盖率高；只展示事实与风险，不渲染正向结论 |

样本覆盖率低于 90% 时，所有统计结论均加“样本不完整”标记；`upRatio` 不可用时，不以榜首股票代替整体。

### 4.2 因果层匹配

详情页不新增 Prompt。将早报缓存构建为可查询索引，但不能只按板块名称硬匹配。

匹配优先级：

1. 精确板块名；
2. 预设别名/细分映射；
3. `relatedSectors` 命中；
4. 仅在有共同 `evidenceIds` 时采用弱匹配。

每次匹配返回 `matchQuality: exact | related | weak | none`。只有 `exact`、`related` 可展示“可信催化”；`weak` 只能表述为“可能相关，尚待验证”；`none` 显示“当前仅观察到行情变化，未匹配到充分驱动证据”。同时展示早报生成时间与行情时间，避免把过期早报解释成当日原因。

字段映射：

| 页面字段 | 主来源 | 兜底 |
| --- | --- | --- |
| 今天发生了什么 | P1 `what` + 因果链起始事实 | `bubbleConclusion` / 规则事实 |
| 可信催化 | P2 `supportingEvidence` + P3 `supportingEvidence` | 不展示列表 |
| 反向证据 | P2 `counterEvidence` + P3 `counterLogic` | “暂无额外反证，但不代表风险不存在” |
| 可信度 | 计算层优先，辅以 P2/P3 | `limited` |
| 未来观察 | P3 `observationIndicators` | 现有 `watchPoints` |

### 4.3 代表股票

使用 `representativeStocks` 替代含义模糊的 `leadingStocks`，分为：今日强势、行业龙头、异动。

- **今日强势**：涨幅、成交额、换手率、市值均先转为同板块百分位，再按 40/30/20/10 加权，避免不同量纲直接相加；
- **行业龙头**：市值与成交额交集，缺失时只展示可用维度；
- **异动**：量比 > 3 且价格上涨，缺失量比时不强行判定。

每只股票只显示名称、涨跌幅、分类与入选原因。不得使用“推荐”“机会”“低吸”等交易导向表述。

### 4.4 缓存、时效与降级

`/api/sector-detail` 中行情、广度、新闻、早报索引并行拉取；每个子任务独立超时和降级，不能因新闻或东财单接口失败让整个详情页失败。

- 行情/广度：短缓存；
- 新闻：中等缓存；
- 早报因果：跟随 morning-report 的有效期；
- 页面显示“行情更新于 / 解释生成于 / 新闻时间”。

## 5. 接口契约

在现有 `/api/sector-detail` 上新增、而非破坏既有字段：

```ts
{
  insight: {
    whatHappened: string,
    matchQuality: 'exact' | 'related' | 'weak' | 'none',
    evidenceStatus: 'confirmed' | 'market_only' | 'insufficient',
    supportingEvidence: string[],
    counterEvidence: string[],
    confidence: { level: 'high' | 'medium' | 'limited', explanation: string },
    observationIndicators: string[],
    generatedAt?: string
  },
  health: {
    status: 'broad_rise' | 'leader_driven' | 'divergence',
    presentation: 'broad_rise' | 'leader_driven' | 'divergence' | 'broad_fall',
    upRatio: number | null,
    sampleCoverage: number | null,
    leaderContribution: number | null,
    dispersion: number | null,
    limitUpCount: number | null,
    dataAsOf?: string
  },
  representativeStocks: {
    strength: Stock[],
    leaders: Stock[],
    unusual: Stock[]
  }
}
```

旧字段保留一个版本周期，前端迁移完成后再清理。

## 6. 交互与视觉规范

- 底部抽屉使用语义化 `dialog` 行为：Esc 关闭、焦点进入抽屉、关闭后回到触发板块、背景滚动锁定。
- 关闭与关注按钮的点击区域至少 44×44px，并提供中文 `aria-label`。
- 不再使用大量同型圆角卡片嵌套；结论区是清晰的内容块，数据表使用轻分隔线。
- 涨跌继续遵循 A 股红涨绿跌，但文字、图标和正负号共同表达，不能只依赖颜色。
- 彩色浅底上的文字使用对应色系深色，避免灰字在彩色背景上降低对比度。
- 动画仅保留抽屉进出；支持 `prefers-reduced-motion`。

## 7. 实施顺序

1. 扩展 `fetchSectorBreadth` 与纯函数测试（覆盖率、P90-P10、健康度、代表股排序）。
2. 将 morning-report 构建为带 `matchQuality` 的板块索引缓存。
3. 改造 `/api/sector-detail`，并行聚合数据并实现独立降级。
4. 扩展 `SectorDetailPanel` 类型与数据适配层。
5. 重排首屏与四组二级内容，修复默认展开区块不存在的问题。
6. 实现键盘、焦点、空状态、时间戳与低动态偏好。
7. 回归验证：普通板块、泡泡精选入口、无新闻、样本不完整、行情源超时、移动端。

## 8. 验收标准

- 打开详情后 1 秒内可见板块结论区域；核心结论不依赖用户展开。
- 每个结论都能显示数据时间、匹配质量或“证据不足”。
- 无新闻、早报未生成、东财单接口失败时，页面仍展示可用行情与明确降级说明。
- 代表股不出现交易建议，且每组都有可解释的入选原因。
- 键盘可完成打开、浏览、关闭；移动端无横向溢出。
- 泡泡精选、早报、普通市场地图三种入口均不会互相覆盖或制造重复 AI 请求。
