# 条件选股功能说明

> 更新日期：2026-08-24
> 定位：为多 Agent 个股分析提供**可解释的研究候选池**，不输出自动买卖建议，也不会批量启动个股 Agent。

## 已实施能力

### 1. 自然语言条件选股

- 用户用自然语言输入行情、估值、财务、行业或指数成分条件。
- 服务端调用东方财富妙想 `stock-screen` 接口，`MX_APIKEY` 仅存在 Node 服务端，不会发送到浏览器。
- 返回候选数量、字段表格、解析后的条件链和数据时点。
- 同一查询 10 分钟服务端缓存；用户点击“刷新筛选”才会绕过缓存回源。

### 2. 条件可视化编辑

- 妙想已识别条件展示为标签。
- 用户可以移除已识别条件，或补充一条文字条件。
- 点击“应用并重新筛选”后，将编辑后的条件重新发给妙想解析；前端不会假设字段语义或本地拼造结果。

### 3. 结果内二次筛选与排序

- 支持在当前候选结果中按名称/代码搜索。
- 可选择当前接口实际返回的任意数值字段，做“大于等于 / 小于等于”二次筛选。
- 支持点击表头升降序排序。
- 二次筛选只作用于当前最多展示的前 200 条接口结果；页面明确显示当前展示覆盖范围。

### 4. 研究篮、自选与个股分析入口

- 候选股可加入本次会话的研究篮。
- 可直接加入现有“我的关注”。
- 只有用户主动点击“分析”或从研究篮进入时，才进入现有个股分析流程并按需调用对应 Agent。

### 5. 已保存条件与每日更新

- 登录用户可保存最多 12 条常用条件，服务端按用户隔离。
- PostgreSQL 可用时写入 `saved_screeners`；本地未连库时按既有策略回退内存仓储，因此重启会丢失，这是开发环境限制。
- 每天上海时区 09:30，系统最多刷新 60 条已启用保存条件。
- 刷新后记录候选数量、候选新增、移出及排名变化；用户也可在页面手动刷新某条条件。
- 日更只调妙想选股接口，不调用 AI，不批量触发个股研究。

### 6. 结果解释与数据质量

页面会展示：

- 查询原文与解析条件；
- 数据时点、来源、实时/缓存状态；
- 总命中数与展示行数；
- 当前展示字段中的空值数量；
- 候选池限制说明：条件命中不等于投资结论，仍需进入个股分析核验。

## 接口

| 接口 | 作用 | 登录 |
|---|---|---|
| `POST /api/stock-screeners` | 运行自然语言条件选股 | 否 |
| `GET /api/saved-screeners` | 查询当前用户已保存条件 | 是 |
| `POST /api/saved-screeners` | 保存条件 | 是 |
| `POST /api/saved-screeners/:id/refresh` | 强制刷新一条保存条件并更新变化记录 | 是 |
| `DELETE /api/saved-screeners/:id` | 删除一条保存条件 | 是 |

## 数据库迁移

`backend/db/schema.sql` 已新增 `saved_screeners` 表。生产环境配置 `DATABASE_URL` 后执行现有迁移即可建表；不需要额外暴露妙想密钥。

## 当前边界

- 条件标签来自妙想解析，编辑后会重新交由妙想理解，避免本地条件解释与数据口径不一致。
- 当前结果接口最多返回/展示 200 行，不应把未展示范围理解为无更多候选。
- 尚未实现跨条件横向对比、历史回测、选股提醒推送和回测收益展示。
