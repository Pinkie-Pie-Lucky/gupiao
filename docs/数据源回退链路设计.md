# 多源数据回退链路设计

## 目标

在不伪造数据的前提下，为行情、公司资料、公告财报和情绪数据建立可观测的多源回退机制。每次返回都携带来源、数据时间、新鲜度和回退层级，前端据此展示可信度。

## 数据分类与功能

| 类别 | 产品功能 | 主数据源 | 已验证回退源 | 不可替代规则 |
| --- | --- | --- | --- | --- |
| A 股实时行情 | 首页指数、市场温度、个股详情、代表股 | 腾讯财经 | 新浪财经 → 雪球行情 → 最近成功快照 | 缓存行情不可参与“今天上涨/放量”的实时归因 |
| 港股实时行情 | 港股个股评估、关联公司 | AKShare 港股现货 | 最近成功快照 | 当前没有第二个已验证的港股实时源 |
| 公司画像 | 个股评估基础档案、主营业务、管理层 | 雪球 F10 | CNINFO 披露文件 → 最近资料快照 | 不补写未知的公司事实 |
| 公告与财报 | 财报解读、业绩、风险、减持、回购、互动易 | CNINFO | 已解析报告缓存 → 原始公告链接 | 财务数字以 CNINFO 对应报告期为准 |
| 市场关注度 | 热门股、情绪异常、关注变化 | 雪球讨论/关注榜 | 最近热度快照 | 热度不能作为基本面事实 |

## 新增候选数据源（2026-08 验证，尚未全部写入产品链路）

| 数据源 | 已验证能力 | 计划用途 | 接入约束 |
| --- | --- | --- | --- |
| 妙想 `mx-search` | 金融新闻、公告、研报、政策、规则，返回关联证券与正文块 | 事件、行业政策、舆情的金融资讯主搜索源 | API Key 仅在服务端；保留原始来源、日期、链接和调用额度状态 |
| 妙想 `mx-data` | 行情、资金、财务、公司关系和经营数据 | 行情/财务交叉校验及新增回退源 | 上线前逐项验证复权、时间戳、单位与报告期口径 |
| 妙想 `mx-xuangu` | 自然语言条件选股、行业/指数成分和结果统计 | 行业成员快照、可比样本、研究候选池 | 结果是筛选候选，不是买入推荐；保存解析后的筛选条件 |
| 知乎官方开发者接口 | 知乎搜索、全网搜索、热榜 | 社区内容与观点首个正式来源 | 已有客户端，尚未进入舆情快照；遵守内容存储与授权范围 |
| 百度/头条/B站/抖音/知乎公开热榜 | 热点标题、热度和链接 | 宏观/政策/行业/公司热点候选 | 网页内部接口，仅作发现；头条需 `origin=toutiao_pc`；设置限频和健康监控 |
| `ddgs` | 多搜索引擎标题、链接、摘要 | 全网线索和金融搜索失败后的发现回退 | 非官方稳定 API，可能限流、验证码或 403；限定白名单域名并缓存 |
| 微博网页热搜 | 当前返回 403 | 暂不接入 | 等待官方授权或稳定数据接口 |

新增数据源必须先进入统一原始证据层，再按语义进入对应回退链。禁止用热榜补金融事实、用新闻补社区观点、用搜索摘要补官方公告。

## 统一数据契约

```ts
type SourceMeta = {
  source: 'tencent' | 'sina' | 'xueqiu' | 'cninfo' | 'akshare_hk' | 'mx_data' | 'mx_search' | 'zhihu' | 'baidu_hot' | 'toutiao_hot' | 'bilibili_hot' | 'douyin_hot' | 'ddgs' | 'cache';
  fetchedAt: string;
  asOf?: string;
  freshness: 'realtime' | 'delayed' | 'stale';
  confidence: 'official' | 'market' | 'sentiment' | 'limited';
  fallbackLevel: 0 | 1 | 2 | 3;
};
```

所有接口必须返回 `sourceMeta`。源失败时记录原因；仅在有最近成功快照时返回 `stale`，没有快照时返回明确的不可用状态。

## A 股行情回退链（第一阶段）

```text
请求 → 15–60 秒内存缓存
     → 腾讯财经（主源）
     → 新浪财经（字段校验后作为第二源）
     → 雪球行情（最后实时回退）
     → 最近成功快照（展示数据时间和“非实时”标识）
     → 不可用（不生成行情驱动结论）
```

字段必须在同一来源、同一时间戳内使用，不拼接不同源相差超过三分钟的数据。

## 财报与公告链（第二阶段）

```text
报告期结构化缓存 → CNINFO 公告检索 → 原始报告文件 → 解析与校验
                                              ↓
                                      仅展示原始公告链接和“待解析”
```

财务字段需要标记 `official_verified`、`official_document_only`、`stale` 或 `unavailable`。无权威数值时不参与估值或经营评分。

## 公司画像与情绪链（第三阶段）

```text
雪球 F10（7 天缓存） → CNINFO 公司披露 → 最近资料快照
雪球热度（10–30 分钟缓存） → 最近热度快照 → 不展示热度
```

## 金融资讯、社区舆情与热点发现链（第四阶段）

```text
公司事实：CNINFO → mx-search 官方/权威来源 → 最近成功事件快照 → unavailable
金融资讯：mx-search → ddgs 白名单网页 → 最近成功资讯快照 → unavailable
社区观点：知乎官方接口 → 后续授权平台接口 → unavailable
热点发现：百度/头条/B站/抖音/知乎热榜 → ddgs → 不生成候选
```

平台热榜只生成待核验候选；只有完成股票实体匹配、来源分级、去重和官方/独立来源交叉验证后，才能进入事件或舆情快照。

## 实施顺序

1. 实现 A 股腾讯 → 新浪 → 雪球 → 缓存回退，并在首页输出来源元数据。
2. 接入 CNINFO 公告检索、报告期缓存和财报解析契约。
3. 接入雪球 F10 与热度，作为公司画像和解释层。
4. 为港股链补测第二个实时源，并补齐自动化验收和数据源健康监控。
5. 接入 `mx-search` 与知乎官方接口，建立原始资讯/社区内容证据表、证券实体匹配和去重事件簇。
6. 将 `mx-data` 作为行情、财务和关系数据的交叉校验源，并逐项验证口径后再纳入自动回退。
7. 使用 `mx-xuangu` 建立行业成员、可比样本和研究候选池，不将筛选结果直接写成投资建议。
8. 接入平台热榜和 `ddgs` 作为热点发现与全网回退，补齐来源健康监控、限频、缓存和降级测试。
