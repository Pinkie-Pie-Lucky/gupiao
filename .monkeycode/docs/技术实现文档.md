# 泡泡看市 — 技术实现文档

## 项目概况

| 项目 | 说明 |
|------|------|
| 名称 | 泡泡看市 (Paopao KanShi) |
| 定位 | AI 智能投研助手（A 股模拟） |
| 技术栈 | React 19 + TypeScript + Vite 6 + TailwindCSS 4 + Express + Google Gemini |
| 运行架构 | 前后端一体（Express 同时托管 Vite 前端开发服务 + API 路由） |
| AI 模型 | Google Gemini `gemini-3.5-flash` |
| 入口 | `server.ts` 启动在 `0.0.0.0:3000` |

## 核心模块功能说明

### 1. 首页 (HomeTab)

`src/components/HomeTab.tsx`

#### 1.1 AI 老师每日早报

```
"早上好！今天市场整体上涨，AI 板块领涨，成交额增加 12%。如果今天只记住一件事，就是资金重新回到了科技板块。"
```

| 属性 | 说明 |
|------|------|
| **实现方式** | 硬编码文本 |
| **数据来源** | 组件内直接写死的字符串 |
| **是否 AI** | 否 |
| **是否动态** | 否，每天显示相同内容 |

#### 1.2 早报原因解读（底部弹窗）

用户点击早报卡片上的"查看原因"按钮后，弹出全屏原因解读面板，展示三因素分析：

- **核心催化**：全球算力链超预期
- **资金风向**：主力大单净买
- **流动性保障**：央行逆回购

| 属性 | 说明 |
|------|------|
| **实现方式** | 硬编码文本卡片 |
| **数据来源** | 组件内直接写死的三组字符串 |
| **是否 AI** | **否**，与 AI 无关 |
| **为什么不是 AI** | 这段文字无论何时打开都是固定内容，不存在"根据每天不同信息给出不同原因"的机制。当前版本的早报和原因解读是静态文案。 |

**结论：这个功能目前没有使用 AI，也无法根据每日信息动态变化。如果要实现动态化，需要接入真实行情 API 获取当日市场数据，再将数据注入 AI 提示词生成解读。**

#### 1.3 泡泡解读（今日事件卡片）

三张卡片"今日最大热点"、"板块涨跌分化"、"重要财经事件"，每张都带有"泡泡解读"段（🤖 图标）。

| 属性 | 说明 |
|------|------|
| **实现方式** | 硬编码文本 |
| **是否 AI** | 否，虽然使用了 🤖 图标暗示 AI 生成，但实际上是静态文案 |

#### 1.4 今日学习（泡泡老师指导）

`LEARNING_KNOWLEDGE` 数组包含 6 条金融小知识（放量、回踩、换手率、超买、洗盘、底背离），随机展示一条，可点击切换。

| 属性 | 说明 |
|------|------|
| **实现方式** | 硬编码数组 + `useState` 随机索引 |
| **是否 AI** | 否 |

#### 1.5 实时指数跳动

上证、深证、创业板三大指数，每 4 秒通过 `setInterval` 微调数值，模拟行情软件实时跳动效果。

| 属性 | 说明 |
|------|------|
| **实现方式** | `useEffect` + `setInterval(4000)`，在现有数值基础上加一个小随机值 |
| **数据来源** | `data.ts` 中的 `initialIndices`，初始值为硬编码 |
| **是否 AI / 真实行情** | 否，纯前端随机数模拟 |

### 2. 泡泡老师 AI 对话 (AiTeacherTab)

`src/components/AiTeacherTab.tsx` — **这是项目中真正调用 AI 的两个功能之一。**

#### 2.1 工作流程

```
用户输入文字
  → 前端构造 { message, history (最近 4 条) }
  → POST /api/chat
  → Express 服务端调用 Google Gemini API
  → Gemini 返回 AI 生成回复
  → 前端渲染回复（含建议追问提示词）
```

#### 2.2 AI 提示词工程

服务端 `server.ts` 中为 Gemini 设置了 `systemInstruction`（系统指令），这是提示词工程的核心：

```
你是"泡泡老师" (Paopao Teacher)，一个非常可爱、亲切、专业且富有幽默感的
A股智能投资研究专家，服务于"泡泡看市"应用。
```

**提示词包含以下设计要素：**

| 设计维度 | 具体内容 |
|----------|----------|
| **人设塑造** | 可爱的泡泡老师，自称"泡泡"、"泡泡老师"、"泡泡看到"，用活泼语气（"加油！"、"🎈"、"💡"） |
| **专业能力** | 宏观大市分析、个股技术面研判、资产配置决策，使用专业术语（主力资金流、均线托底、回踩布林线下轨等） |
| **术语解释强制** | 每个专业术语必须在括号内或紧随其后用通俗语言解释（如"高位筹码松动"指买卖双方出现分歧，原本坚定的买家开始卖出，股价容易不稳） |
| **合规约束** | 不制造恐慌/贪婪情绪，不给买卖建议，回复末尾必须加免责声明 |
| **教育定位** | 帮助用户理解逻辑和资金动向，不做短期涨跌预测 |
| **输出控制** | 150-280 字，简体中文，粗体 + 列表排版 |
| **生成参数** | `temperature: 0.7`，保持一定创造性 |

#### 2.3 上下文管理

每次请求将最近 4 条历史消息传给 Gemini，实现多轮对话记忆。消息格式转换为 Gemini 的 `contents` 数组格式。

#### 2.4 智能建议提示词

根据用户提问内容动态匹配后续建议：
- 包含"算力"、"AI"→ 推荐算力板块相关问题
- 包含"半导体"、"芯片"→ 推荐半导体相关问题
- 默认情况 → 推荐通用的技术分析问题

#### 2.5 前端配合

- 支持从其他页面跳转并预填股票（如"分析个股 科大讯飞 (002230) 的技术走势..."）
- 监听全局 CustomEvent `trigger-ai-chat` 接收搜索无匹配的关键词
- 语音播报功能（Web Speech API），朗读 AI 回复的前 200 字符
- Markdown 粗体高亮渲染

### 3. 一键解盘 (OneClickMarketModal)

`src/components/OneClickMarketModal.tsx` — **项目中真正调用 AI 的两个功能之二。**

#### 3.1 工作流程

```
用户点击"一键解盘"按钮
  → 前端 POST /api/market-report（空 body）
  → 服务端用硬编码行情数据构造 prompt
  → 调用 Gemini API 生成结构化解盘报告
  → 前端展示报告 + 语音朗读
```

#### 3.2 AI 提示词设计

服务端将大盘数据直接嵌入 prompt：

```
针对今天以下A股大市数据进行一键深度研判：
- 上证指数：3026.49点，上涨 +0.72%
- 深证成指：9730.87点，上涨 +1.25%
- 创业板指：1905.15点，上涨 +1.48%
- 异动预警：AI算力板块今日涨幅高达 +4.32%，但盘中主力大单资金出现高位松动流出
- 接力板块：国产半导体设备、机器人具身智能放量逆势补涨
```

要求 Gemini 输出三个结构化段落：
1. 【大势泡泡评】— 总结今日走势性质
2. 【泡泡异动警示】— AI 算力板块风险预警
3. 【泡泡埋伏点睛】— 半导体与机器人低吸机会

生成参数：`temperature: 0.5`（比对话更低的温度，追求输出稳定性）

#### 3.3 局限性

| 问题 | 说明 |
|------|------|
| **行情数据硬编码** | prompt 中的指数数值（3026.49、9730.87等）是写死在服务端代码中的，不是从实时行情 API 获取 |
| **前后端数据独立** | 前端 `data.ts` 中的指数数值和服务端 prompt 中的数值虽然一致，但没有实时同步机制 |
| **不是真正的"每日不同"** | 因为数据源是硬编码的，除非手动修改代码，否则每天的"一键解盘"输入数据是相同的 |

### 4. 市场地图 (MarketMapTab)

`src/components/MarketMapTab.tsx`

| 功能 | 实现方式 |
|------|----------|
| 板块热力图 | 6 个硬编码板块（AI 算力、半导体、机器人、新能源、医药生物、白酒消费），每板块 2-4 只成分股 |
| 实时价格模拟 | 每 5 秒 `setInterval` + `Math.random()` 微调所有成分股价格，动态重算板块平均涨跌幅 |
| 板块描述 | 每个板块有预设的硬编码描述文本 |
| K 线图 | 基于 `InteractiveChart` 组件，Recharts 渲染，非 1D 周期的 K 线数据为前端 `Math.random()` 模拟行走 |
| 跳转 AI 老师 | 点击"向泡泡老师提问此股"→ 跳转到 AiTeacherTab 并自动填入该股票 |

## 总结

"早报原因解读"当前是**纯硬编码实现**，并非 AI 驱动。它展示的是写死在组件代码中的静态文案，无法根据日期不同给出变化的原因。

项目中真正使用 AI 提示词工程的是 **泡泡老师对话**（通过 8 大设计维度的 system instruction 塑造人设和行为）和 **一键解盘**（将行情数据嵌入 prompt 让 Gemini 生成结构化报告）。要使早报也能"每天不同"，需要接入真实行情 API 并将当日数据注入 AI 提示词。
